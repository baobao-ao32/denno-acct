# GAS 台帳コア

Cloudflare Worker から JSON を受け取り、Googleドライブ上の年度別スプレッドシートと領収書フォルダを管理する。

## デプロイ手順

1. Googleドライブに「会計」ルートフォルダを作る（既存のものがあればそれを使う）
2. script.google.com で新規プロジェクトを作り、下記の `.gs` ファイルを全て貼り付ける
   （GASではプロジェクト内の全ファイルが1つの名前空間を共有する。ファイル名は自由）
3. プロジェクトの設定 → スクリプトプロパティに以下を設定する
   - `ROOT_FOLDER_ID` — 「会計」ルートフォルダの Drive ファイルID
   - `API_TOKEN` — Worker の Secret と同じランダムな文字列
4. デプロイ → 新しいデプロイ → 種類「ウェブアプリ」
   - 実行ユーザー: 自分
   - アクセスできるユーザー: 全員（Worker がサーバ間通信で叩く。認証はトークンで行う）
   - 発行されたウェブアプリ URL を Worker の `GAS_ENDPOINT` に設定する

## ファイル構成

| ファイル | 役割 |
|---|---|
| `config.gs` | マスタ定義（カテゴリ・科目・支払方法）、台帳ヘッダ、上限値 |
| `main.gs` | エントリポイント `doPost` / `doGet`、トークン認証、振り分け |
| `validation.gs` | ペイロード検証（Worker側と同じルールの二重検証） |
| `fiscal.gs` | 年度判定（4月スタート）、年度環境の保証（フォルダ作成・スプレッドシートのコード生成・ヘッダ検証） |
| `sheets.gs` | シート読み書きの共通部品（ヘッダ名→列番号 経由でのみ操作）、新規シートの書式適用 |
| `receipts.gs` | 代表カテゴリ判定、領収書のハッシュ照合、保存フォルダの移動 |
| `register_income.gs` | 収入の登録 |
| `register_expense.gs` | 支出の登録（領収書保存・用途追記を含む） |
| `actions.gs` | 取消（void）・状態照会（status）・APIログ |
| `aggregate.gs` | 集計タブ（サマリ / 収入 / 支出）の再計算 |

## 動作

- `POST /` に Worker 経由で `{ kind: "income" | "expense", ... }` が届くと、
  年度環境（フォルダ・スプレッドシート・領収書フォルダ）を保証してから追記する
- 収入の年度帰属は報告日、支出は購入日。年度は4月スタート
- 領収書は代表カテゴリ（金額割合が最大のカテゴリ）のフォルダに保存する
- 同じファイル（SHA-256 が一致）の再提出は、用途を既存の取引へ追記する。
  追記で代表カテゴリが変われば、GAS がファイルを正しいフォルダへ移動する
- 同じ `clientRequestId` の再送は二重登録せず、既存の取引IDを返す
- 登録のたびにサマリ / 収入 / 支出タブを再計算して値で書き込む。
  収入・支出タブの「備考」は人間が書く欄のため、再計算の前後で保持する
  （収入は科目名で、支出は「大分類×科目」で引き継ぐ）
- 取消は `POST { action: "void", transactionId, reason }`。行は消さず取消フラグを立てる
- 状態確認は `POST { action: "status", clientRequestId }`
- 領収書の事前照会は `POST { action: "checkReceipt", sha256 }`。登録済みなら取引ID・登録済み金額合計などを返す
- 金額の完全一致（用途合計 = 領収書全体の金額）は登録時に取引単位で検証する。
  分割提出の追記では「登録済み合計 + 今回の合計 = 全体の金額」を要求する

## まだ本番確認していないこと

- このコードはローカルでの構文チェックのみ済み。GAS 上での実動テストは未実施
- 年度スプレッドシートはコードで生成する（テンプレートファイルは不要）。
  タブ・ヘッダ・列幅・金額書式・精算状態のプルダウン・設定タブの初期行は
  作成時に `sheets.gs` の `formatSheet_` が付ける。見た目を変えたいときは
  `SHEET_FORMATS` を編集して再デプロイすること
- 「設定」タブのキー: `前年度繰越金`（金額を手入力。収入タブの繰越金行とサマリに反映される）
