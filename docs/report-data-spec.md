# 会計報告書のための必須データ仕様（2026-11-24）

前提資料:
- 収支報告書テンプレ（xlsx）: 「yyyy年度 団体名 収支報告書」、報告期間 4/1〜翌3/31
- 領収証等一覧テンプレ（pptx, 16:9）: 表紙 + 大分類の見出しスライド（運営費/制作練習費/参加出展費）+ 各空白ページ
- 「会計報告書概要」（工学部学友会役員会, 2024-03-18）: 記入ルールの正本
- 「工学部学友会における分配金に関する規則」（令和6年1月18日制定）: 直接経費と分配金区分の根拠

提出フロー（概要より）: 指定Googleフォームから提出、期限は翌年度4月30日。
収支報告書はExcelを編集してPDF化、領収証等一覧はPowerPointを編集してPDF化して提出する。
**いずれも「ダウンロードしてローカルで編集し、Googleスプレッドシート/スライドのWeb編集は使うな」が公式指示。**
→ 自動生成の出力は編集可能な .xlsx / .pptx とし、PDF化は人間が確認・修正した後に手動で行う。これは当初の希望（生成後に人の目で確認・修正できること）と一致する。

## 1. テンプレから逆算した「報告書が要求するデータ」

### 1.1 ヘッダ・署名（取引データではない。年次のメタデータが要る）
| 項目 | 内容 | 出所 |
|---|---|---|
| 年度 | タイトルと報告期間（yyyy年4月1日〜yyyy+1年3月31日）を決める | 取引日付から導出 |
| 団体名 | 登録されている正式名称。タイトルは「yyyy年度␣団体名␣収支報告書」（半角スペース） | 固定設定（要・正式名称の確認） |
| 会計 署名 | 「姓␣名（所属学科）」例: 田中 太郎（生命工学科） | **年次メタデータ（新規）** |
| 代表 署名 | 同上 | **年次メタデータ（新規）** |

### 1.2 サマリ（全て導出可能）
- 収入合計 / 支出合計 / 差引収支（= 収入 − 支出）
- **領収証等による支出の証明ができない額**: 領収証等一覧に添付できない支出の合計。全て添付できるなら0
  - テンプレxlsxの注意: 冒頭の収入合計セル（H6）は数式ではなく初期値0のベタ値。支出合計（H7=H39）と差引（H9=H6−H7）は数式あり。
    生成時はH6に値を書き込む必要がある（テンプレの数式だけに頼れない）
- 参考値として **直接経費額（≒ 支出合計 − 証明できない額）** も出す。
  分配金規則 別表第2の区分（前年度直接経費 2万/10万/30万/50万/100万円〜）はこの額で決まるため、年度集計に必ず表示する

### 1.3 収入の部（テンプレは最大6行）
列: 科目 / 金額 / 前年度比較増減 / 備考
- 科目は概要の例がほぼ必須の粒度: **工学部学友会分配金 / 工学部学友会役員報酬 / 会費収入 / 農学部学友会分配金** + 頒布・売上、その他
  - ⚠ v2設計の収入カテゴリ（dues / subsidy / sales / other）は粗すぎる。分配金と役員報酬が subsidy に潰れて分離できない
  - → **収入カテゴリマスタを報告科目そのものに再定義する**（下記マスタ案）
- 金額: 科目ごとの年度合計（導出）
- 前年度比較増減: 前年度の同科目合計との差。比較対象がなければ「-」
  - → **前年度の科目別合計が引けることが必須**。IDが年度をまたいで安定している必要があり、初年度は前年度実績を初期データとして手入力する
- 備考: 科目ごとの自由記述。取引データには無い。**報告書ドラフト側で人間が書く**（生成物に空欄で出す）

### 1.4 支出の部（テンプレは最大15行）
列: 大分類 / 科目 / 金額 / 備考
- 大分類は **運営費 / 制作練習費 / 参加出展費** の3種・この順番固定（概要 1-4-1）。各グループの最初の科目行にだけ大分類を書く
  - ⚠ 内部カテゴリ名（サークル運営/制作練習/参加出展）と報告名が違う。マスタに「報告名」を持つ:
    operation → 運営費、practice → 制作練習費、event → 参加出展費
- 科目: 用途で分類した名前（例: 消耗品費、プロジェクトA材料費、配送料、会場使用料）。同一大分類内ではまとめて並べる。異なる大分類に同名科目があってもよい
  - ⚠⚠ **現在のv2明細（用途名=自由文、品目名）には「科目」に相当する項目が無い。**
    用途名をそのまま科目にすると取引ごとに1行になり、15行をすぐ溢れるし、報告書の粒度にもならない
  - → **明細に「報告科目」を新規追加する**（下記マスタ案から選択。追加も可能にする）
- 金額: （大分類, 科目）ごとの年度合計（導出）
- 備考: 科目行ごとの自由記述。ドラフト側で人間が書く
- 15行制限: グループ数が15を超えたら生成器が警告する。科目マスタで粒度を管理するのが前提

### 1.5 領収証等一覧（pptx）
- 構成: 表紙（団体名を中央配置）→ 大分類ごとに見出しスライド + 領収証ページ
- 並び: **大分類ごとにまとめ、収支報告書の科目の記入順に並べる**（= 1.4の並び順と連動する）
- 1枚の領収証が複数カテゴリ/科目に跨る場合: **支出割合が一番大きい科目のところに添付する**
  - → 取引ごとに「代表カテゴリ」と「代表科目」が導出できる必要がある（金額最大の明細の categoryId / 報告科目）
  - v1の receipt.gs が領収書保存先にやっていた「金額最大カテゴリ」ルールと同一。v2では科目まで拡張する
- 視認性: 内容が確認できる大きさで、1ページにできるだけ多く。白紙ページ追加は可
  - → 生成器は領収証画像のアスペクト比からグリッド配置を決める。最小サイズ制約を割ったら次ページへ
  - 確認作業のため、各領収証に小さなキャプション（日付 / 科目 / 金額）を付けることを提案する（概要は禁止していない。人手確認の実用性が段違いになる）
- 領収証ファイル: Driveに保存された原ファイルへの参照（ID・MIME）が必須。
  PDF領収証はpptxに直接貼れないため、生成時に画像化（レンダリング）する工程が要る

## 2. 結論: v2データモデルへの追加・変更

### 追加するもの
1. **明細.報告科目ID（reportSubjectId）** ※支出のみ必須
   科目マスタ（初期値の候補は分配金規則 別表第1 + 概要の例）:
   消耗品費 / 用品費 / 材料費 / 印刷製本費 / 図書資料費 / 通信費 / 賃借料 / 施設利用料（会場使用料）/
   運搬費・配送料 / 参加費登録料 / 保険料 / 保管料 / 医療費 / 燃料費 / 講師料 / 委託費 / 入館料 / その他
   - マスタには表示順（sortOrder）を持たせ、報告書と領収証一覧の並びを決定する
   - 自由追加は許可するが、追加はマスタ登録として扱い、その場限りの自由文にはしない（集計が割れるため）
2. **取引.証明不可フラグ + 理由（任意）**
   領収書が無い支出を登録できるようにする（現フォーム試作は「支出は領収書必須」で送信を止めているが、
   それでは証明できない支出が帳簿から消えて実態とズレる）。
   証明できない額 = フラグONまたは領収書0件の支出取引の合計として導出する
3. **年次レポートメタ（年度ごとに1レコード）**
   団体正式名（固定設定でも可）/ 会計氏名 / 会計学科 / 代表氏名 / 代表学科 /
   前年度科目別実績（移行初年度のみ手入力）/ 科目別備考（ドラフト編集用）
4. **領収証.画像メタ**: DriveファイルID、MIMEタイプ、画像の幅・高さ（配置計算用。生成時に取得でも可）

### 変更するもの
5. **収入カテゴリマスタを報告科目に合わせて再定義**
   | ID | 報告科目名 |
   |---|---|
   | gakuyu_grant | 工学部学友会分配金 |
   | gakuyu_officer | 工学部学友会役員報酬 |
   | dues | 会費収入 |
   | sales | 頒布・売上 |
   | nogaku_grant | 農学部学友会分配金 |
   | other_income | その他収入 |
   （最大6行のテンプレに収まる。繰越金を収入に含めるかは要確認 → §4）

### そのまま使えるもの（既存v2設計で足りている）
- 取引: 日付 / 種別 / 担当者 / 相手方 / 支払方法ID / 合計金額
- 明細: カテゴリID（→大分類）/ 用途名 / 品目名 / 金額 / メモ
- 年度の導出（4月始まり）、ID設計、void（取消）

## 3. 自動生成の境界（どこまで機械にやらせるか）

2層に分ける。層1は必須、層2は試作して判断する。

- **層1: 集計データの生成（GAS側）**
  年度を指定すると、報告書に必要な全数値（科目別合計、前年度増減、証明できない額、直接経費額、
  領収証リスト〔代表カテゴリ・代表科目・並び順付き〕）を1つのJSON / 集計シートに出す。
  ここまでで「必要データを別ページにまとめる」フォールバック（人間がOfficeでテンプレに転記）も成立する
- **層2: テンプレへの流し込み（ローカルPython想定: openpyxl / python-pptx）**
  テンプレファイルをコピーして値と画像を差し込む。レイアウトはテンプレのものを一切作り直さない
  （フォーマット崩れで支給金0円になった他サークルの事故への対策。生成物は .xlsx / .pptx のまま渡し、
  人間がMS Officeで確認・修正してからPDF化する）
  GASにはxlsx/pptxを編集する現実的な手段が無いため、生成器はGASの外に置く

## 5. 確認結果（2026-11-24 Aoba回答で全て解決）
1. 繰越金: **報告しない前提**。ただしスプシからは確認できるようにする → 収入タブに報告対象外の行として置き、サマリに独立項目で出す（management-spec-2026-11-24.md §3）
2. 支出の報告科目: **マスタ選択式**で確定
3. 団体名: **「電脳サークル」**が正式登録名で確定
4. 領収書が無い支出: 発生しない見込みだが、**証明不可フラグは実装する**
